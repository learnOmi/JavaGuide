## 一、背景与目标

L0 把动效"时长"收敛成了 `--jg-dur-sm/md/lg` 三个令牌，但收敛只解决了"值从哪来"，没解决"这个值该属于哪一类动效"。L1 收尾时留下两条明确线索：

1. `GlobalUnlock.vue` / `LayoutToggle.vue` 仍写着 `transition: all`；
2. 存在**刻度外的裸时长**（`0.22s` / `0.25s` / `0.8s` / `0.45s` / `0.5s`）与**同一视觉语言的重复实现**（`@keyframes shake` 在解锁组件里写了两份）。

**目标**：把动效从"一条过渡刻度"升级为"按语义角色的编排层"，并落地一个克制的站点级进编排（滚动揭示）。

**本期不做**：布局重构、交互流程改动、引入任何第三方动效库（沿用项目自研零依赖约定）。

## 二、核心设计：动效令牌按「语义角色」分档

L0 的隐含假设是"所有动效都是过渡，只是快慢不同"。实际存在三类语义根本不同的动效，硬塞进一条刻度会削掉语义：

| 档位   | 令牌                          | 值                        | 语义                             | 代表场景                    |
| ------ | ----------------------------- | ------------------------- | -------------------------------- | --------------------------- |
| 过渡档 | `--jg-dur-sm` / `-md` / `-lg` | `0.15s` / `0.2s` / `0.3s` | 状态切换，**双向可逆、可被打断** | hover、展开、抽屉、slide-up |
| 强调档 | `--jg-dur-emphasis`           | `0.45s`                   | 一次性反馈，**需要被「看见」**   | 密码错误抖动                |
| 循环档 | `--jg-dur-loop`               | `0.8s`                    | 持续动画周期，**与真实时间挂钩** | spinner 转速                |

判定依据：抖动若压进过渡档（≤0.3s），幅度还没走完就结束，语义被削弱；spinner 的 0.8s 不是"过渡得快慢"，而是"每秒转多少度"，跟时间挂钩、不跟状态切换挂钩。因此 **L2 新增 3 个令牌**（`-emphasis` / `-loop` / `-ease-decelerate`），而不是继续往三档过渡刻度里塞值。

配套新增缓动令牌 `--jg-ease-decelerate: cubic-bezier(0.36, 0.07, 0.19, 0.97)`，用于抖动反馈——该曲线原在两处解锁组件里**逐字符重复裸写**。

### 为什么共享关键帧必须放全局层

SFC scoped 样式里的 `@keyframes` 会被 Vue 加 scope 后缀重命名（实测 `mermaid-lazy-spin` → `mermaid-lazy-spin-89f2581e`），**无法跨组件共享**。要共享必须落在非 scoped 的 `styles/index.scss`。

而 scoped 块**只重命名"块内声明"的关键帧**——引用一个未在块内声明的名字（如 `jg-shake`）不会被改写，因此各组件在自己的 `.shake-enter-active` 里写 `animation: jg-shake ...` 能正确解析到全局定义。此结论已在运行时验证（见第六节）。

### 为什么滚动揭示只挑图片与表格

- 排除**代码块**：高度大，位移观感明显，且常带横向滚动，揭示时容易与滚动行为打架；
- 排除**文字段落**：会干扰扫读节奏，长文里每段都淡入是负体验；
- 排除**标题**：与 TOC 高亮滚动存在语义重叠，两套"出现"信号会互相干扰。

只动 `transform` / `opacity` 两个合成层属性，**不碰** `height` / `margin` / `padding`，从机制上规避布局位移（CLS）。

## 四、计划外发现（两处，均未在计划中预见）

### 4.1 plain-CSS `<style>` 块里的 `//` 注释会击穿 PostCSS（**构建期事故**）

#### 现象

改动完成后 dev server 出现整页 500：页面空白、`#app` 无子元素、存在 `<vite-error-overlay>`、所有 `--jg-*` 令牌取值为空串。控制台报 `Failed to load module script: MIME type of "text/html"`。

直接请求出错的样式模块，拿到确切错误：

```
[postcss] .../LazyMermaid.vue?vue&type=style&index=0&scoped=89f2581e&lang.css:31:28: Unknown word linear
```

#### 根因

我在样式块里补注释时统一用了 `//`，但**两类样式块的解析路径不同**：

| 写法                                      | 预处理                               | `//` 是否安全                                                      |
| ----------------------------------------- | ------------------------------------ | ------------------------------------------------------------------ |
| `<style lang="scss" scoped>`              | 先过 Sass                            | **安全**，Sass 会剥离 `//`                                         |
| `<style scoped>` / `<style>`（无 `lang`） | 直达 PostCSS（URL 后缀 `&lang.css`） | **不安全**，`//` 不是合法 CSS 注释，会把后续声明一并吞成非法 token |

本轮中招的三个文件都是无 `lang` 的：`LazyMermaid.vue`（`<style scoped>`）、`UnlockContent.vue`（`<style scoped>`）、`GlobalUnlock.vue`（`<style>`）。同批用了 `//` 的 `LayoutToggle.vue` / `DocEditor.vue` / `NewPageDialog.vue` 均为 `lang="scss"`，安然无恙——这正好构成对照。

#### 处置

把上述三个文件里的 `//` 注释统一改为 `/* */`（保留全部注释文字，未删减）。修复后三个样式模块均返回 200，页面恢复正常。

#### 留给后人的硬规则

> **在 `.vue` 的样式块里补注释前，先看 `<style>` 有没有 `lang="scss"`。没有 `lang` 的一律用 `/* */`。**

附带教训：这类错误**只在 dev server 运行时暴露**。静态源码扫描（我此前做的那一轮）完全查不出来——它扫描的是源文件文本，而问题出在编译路径上。所以"源码扫描通过"不能替代"运行时/构建验证"。

### 4.2 快速滚动 / 直达底部会让正文永久不可见（**验收期发现，已修复**）

本轮最严重的一个缺陷。它是**在用户复核时质疑"L2 是不是真的完成了"之后才被挖出来的**——第一轮验收给出了**假阳性**。

#### 现象

模拟用户按 `Ctrl+End`（或拖动滚动条）直达页底：

| 页面 / 场景                                                      | 候选元素 | 结果                                  |
| ---------------------------------------------------------------- | -------- | ------------------------------------- |
| `collection-api-for-algorithms.html` · 直达底部                  | 8 个表格 | **8/8 卡在 `opacity: 0`，永久不可见** |
| `collection-api-for-algorithms.html` · 快速滚屏（800px / 115ms） | 8 个表格 | **7/8 卡在 `opacity: 0`**             |

这些元素的 `top` 已是 `-28427` 这类"早就滚过头"的值，但始终没被揭示，而且**不会再有任何机制去揭示它们**。

#### 根因

`IntersectionObserver` 只在**相交状态发生变化**时回调。元素从「视口下方（不相交）」一次性跳到「视口上方（同样不相交）」，状态**全程没变过**，回调永不触发。

`unobserve` 又只在揭示时调用，所以这些元素既不会被揭示、也不会被放弃——永久停在初始的 `opacity: 0`。原来的 `rootMargin: "0px 0px -10% 0px"` 只收窄下边界（用于提前触发），对"被跨过去"的元素**没有任何兜底**。

**为什么第一轮验收没抓到**：第一轮用的是 110ms / 800px 的逐屏滚屏，节奏恰好慢到每个元素都被采样到；而"直达底部"是一步到位、状态从不变化。**覆盖度不足的验收方式掩盖了缺陷**——"跑过了"不等于"没问题"。

#### 处置

把 `rootMargin` 的上边界外扩一个极大值，使「视口上方」也算相交，从而让上述跳转产生「不相交 → 相交」的状态变化：

```ts
const ROOT_MARGIN_TOP = "100000px";
const ROOT_MARGIN_BOTTOM = "-10%";
const ROOT_MARGIN = `${ROOT_MARGIN_TOP} 0px ${ROOT_MARGIN_BOTTOM} 0px`;
```

取有限值而非 Infinity（CSS 无法表达无穷）：站点最长页面约 4 万 px，该值绰绰有余；即便某页更长，元素在用户回头上滚时仍会变为相交并被揭示——**失败模式从"永久不可见"退化为"暂时未揭示"**。

选它而不是加 `scroll` 监听，是为了保持"纯 IO、无额外监听器"的原有形态，零新增运行时开销。

#### 修复后复测

| 场景                                 | 结果                                            |
| ------------------------------------ | ----------------------------------------------- |
| 8 表格页 · 直达底部                  | **8/8 揭示，0 卡死**，opacity 全为 1            |
| 8 表格页 · 快速滚屏（800px / 115ms） | **8/8 揭示，0 卡死**                            |
| 18 候选页 · 直达底部                 | **18/18 揭示，0 卡死**，`minOpacity = 1`        |
| 首屏元素是否被误隐藏                 | 仍为 0（`hiddenInViewport: 0`）                 |
| 加载时是否被误揭示（效果是否被破坏） | 仍为 0（`revealed: 0`），渐次揭示的观感未被削弱 |
| 横向溢出                             | `scrollWidth == clientWidth`（1270 / 1270）     |

## 五、与计划的其他偏差

1. **未新增 `.jg-anim-shake` 工具类**。计划里写了要加一个工具类，实施时**有意省略**：两个消费方各自的 `.shake-enter-active` 已经足够表达意图，再加一个只有两处引用、且要被 `!important` 或额外选择器覆盖的工具类，属于死代码。改为各处直接引用全局 `jg-shake` 关键帧。
2. **`RevealOnScroll` 增加"跳过首屏已在视口内的元素"**。计划未细化此点。原因是 SSR 预渲染：若挂载时给"已经在视口内"的元素加 `opacity: 0`，用户会看到**内容先出现→消失→再淡入**的闪烁。因此 `scan()` 里显式跳过 `getBoundingClientRect().top < innerHeight` 的元素——它们保持自然可见，永不进入揭示流程。

### 6.4 `prefers-reduced-motion` 兜底

- **代码路径已审**：`RevealOnScroll` 在 `onMounted` 开头即 `window.matchMedia("(prefers-reduced-motion: reduce)").matches` 早退（完全不介入，内容保持自然可见）；另有 `!("IntersectionObserver" in window)` 第二条降级路径，避免"加了初始态却永远等不到揭示"导致正文永久不可见。全局 `html *, html *::before, html *::after` 的 reduced-motion 归零规则已在 L0 存在，新增动效自动被兜住。
- **运行时未直测**：当前 Playwright MCP 工具链**没有 media emulation 能力**（无 `emulateMedia` 类工具），无法在真实浏览器里强行打开该媒体特性。此条如实标注为"代码路径已审、运行时未直测"，**不构成已验证结论**。

## 七、遗留与说明

- **两个解锁组件当前仍无页面使用**（`GlobalUnlock.vue` 未被 `client.ts` import；`UnlockContent.vue` 虽注册但全库 markdown 零引用，此事实 L1 已查证）。因此 **shake 收敛的当前线上影响为 0**，属"防止后续启用时两套观感打架"的预防性收敛。若后续启用，需真机复测一次抖动观感。

- reduced-motion 的运行时直测仍是空白，列入下期可选补测项。**这一条必须明确标注为"未验证"**：它只有代码路径审查与产物规则静态确认，没有真实浏览器证据（工具链缺 media emulation），不能当作已验证结论引用。

### 教训：验收方式决定能不能挖出缺陷

- **第一轮给出的是假阳性**。我用"110ms / 800px 逐屏滚动"作为滚动验证手段，而这个节奏恰好慢到每个元素都被采样到，于是 8/8 全绿——但换一种"真实用户会做"的操作（`Ctrl+End` 直达底部），缺陷立刻暴露。**"跑过了"不等于"没问题"，验收用例的覆盖度本身就是风险面。**
- **验收必须覆盖"极端操作路径"，不能只走"温和路径"**。滚动揭示这类依赖可见性状态的机制，至少要覆盖：逐屏慢滚、快速滚屏、一键直达底部、锚点跳转、路由切换、刷新后回看。本轮只做了第一种，代价就是漏判。
- **"源码扫描通过"不能替代"运行时/构建验证"**。4.1 的 PostCSS 事故在源文件文本层面完全看不出（问题出在编译路径），4.2 的缺陷在源码层面也自洽（逻辑没错，是浏览器行为与预期不符）。两者都只有真跑起来才会现形。
- **修完要验证"修复进了产物"**，而不只是"源码改了"。本轮专门从 `dist` 压缩产物里挖出 `Pf="100000px"` 作为证据，就是为了堵住"源码修了、产物没跟上"的假通过。
- 构建环境备注：本机 `pnpm docs:build` 需要在沙箱外执行（构建会往 `D:\_tmp_*` 写临时文件，沙箱会拒绝）。
