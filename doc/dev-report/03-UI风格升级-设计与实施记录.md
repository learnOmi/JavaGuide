> 状态：已完成（生产构建产物级验证受阻，见第六节）

## 一、背景与目标

站点的视觉与交互是"逐点补丁"式累积出来的，存在三处结构性债务：

1. **无设计令牌**：`styles/config.scss` 只有一行 `$theme-color`，`styles/palette.scss` 只有侧边栏宽度与字体栈。圆角、阴影、动效时长、缓动曲线、z-index、颜色字面量全部散落在 11 个组件的 `<style>` 块里（z-index 一个属性就有 `10/11/200/300/350/400/500/999/9999` 九种取值）。
2. **动效即卡顿源**：`styles/index.scss` 把 `margin/padding/width` 也放进了 `transition`，这三者每帧都触发 Recalculate Style + Layout，是沉浸模式切换掉帧的主因。全项目 **零处** `prefers-reduced-motion`。
3. **权重战争 + 死选择器**：沉浸模式靠批量 `!important` 压制主题内部类名，其中 5 个选择器指向**根本不存在的元素**，并且**漏掉了真正约束正文列宽的元素**——沉浸模式其实从未真正放宽过阅读列宽。

**目标**：把上述三项一次性收敛为可持续维护的地基，视觉变化只允许出现在"刻意修复"的两处（沉浸模式列宽、动效帧率）。**不做**组件库替换、不做布局重构、不做配色改版。

### 3.2 计划外修复：`$vp-font` 被静默丢弃

**现象**：dev 日志出现 `WARNING: Unexpected variable value: getting system-ui, -apple-system, Segoe UI, ...`，调用栈 `color-is-legal() ← get-variables() ← inject()`。

**根因**：Sass 中不带引号的 `system-ui, -apple-system, ...` 是空格分隔的 **list**，`meta.type-of()` 返回 `list`，不满足 `@vuepress/plugin-sass-palette` 的 `number or string` 判定 → 走 `@warn` 并**静默丢弃**（构建不报错）。

**影响面**：`--vp-font` 从未被注入 `:root`，此前一直靠 `FontSwitch.vue` 在 `applyFont()` 里 `root.style.setProperty("--vp-font", ...)` 内联补救——也就是说**字体只有经过切换器才生效**，首屏默认字体实际走的是主题兜底栈。

**修复**：改为外层 `"` + 内层 `\"` 转义的带引号字符串（与主题 `templates/palette/font.scss` 写法对齐；`\'` 无法跨 `@import`/`@forward` 边界存活，故不能用外层单引号）。修复后该告警消失，`--vp-font` 已注入 `:root`。

**衍生提醒**：`components/fontOptions.ts` 的 `SANS_STACK` 与本令牌内容一致但同样未加引号——它是运行时内联到 `element.style` 的，不受此限制，无需改动。

### 3.3 沉浸模式修复：必须同时归零 `#app` 的 `--sidebar-space`

**基线实测暴露的真相**：常规模式下 `[vp-content]` 的 `max-width` 是 `780px`，但它的 `getBoundingClientRect().width` 是 **860px**——说明**真正卡住可用宽度的不是 `max-width`，而是 `.vp-page` 的 padding**（主题公式：`padding-inline-start: calc(var(--sidebar-space) + 2rem)`、PC 档 `padding-inline-end: calc(100vw - var(--content-width) - var(--sidebar-space) - 6rem)`，是"有侧栏"语义下的非对称值）。

**因此修复需要三件一起做，只改 `max-width` 会"改了但没效果"**：

1. `[vp-content]:not(.custom) { max-width: var(--jg-immersive-content-width) }`（选择器从 `.vp-content` 这个不存在的 class 改为 `[vp-content]` 属性选择器）；
2. `html.layout-hidden #app { --sidebar-space: 0px }`——`--sidebar-space` 声明在 `#app`（id 选择器）上，只在 `html` 上改会被直接声明的 `#app` 压过（继承永远输给同级声明）；
3. `@media (min-width: 960px) { .theme-container .vp-page { padding-inline: var(--jg-immersive-pad-x) } }`——把非对称 padding 整体换成两端对称值，`[vp-content]` 的居中才成立。

另外删除了 5 个死选择器：`.theme-hope-content`、`.vp-page-content`、`.vp-page-container`、`.vp-sidebar-wrapper`、`.sidebar-wrapper`（主题组件从不输出这些类名）；以及并列书写的 `.theme-container > main`（与 `.vp-page` 是同一元素）。

## 五、被否决的方案（记录以免重复讨论）

- **`@layer` 做图层治理**：主题 CSS **全部未分层**，而按 CSS 规范未分层样式优先级**高于**任何分层样式。把自己的覆盖放进 `@layer` 会**更弱**，反而压不住主题。故本期不引入（要正确使用需连主题样式一起分层，须改主题源码）。
- **引入第三方动效库 / UI 库**：用户已明确选择自研零依赖，动效只用 CSS 变量 + 原生过渡。
- **改 `.vp-page` 的 `margin` 来居中**：`[vp-content]` 自身已有 `margin: 0 auto`，额外声明属重复。

**`!important` 退役说明**：本期只摘除主题**完全无对应声明**的属性的 `!important`（如 `.vp-navbar` 的 `opacity` / `pointer-events`），以及靠特异性即可取胜的过渡层（`html .vp-navbar` 等，特异性 (0,1,1) vs 主题 (0,1,0)）。其余位置保留 `!important`，未做激进摘除。
