## 一、背景与目标

前三根支柱各自补了一个维度：L0 把颜色/尺寸/圆角/阴影从字面量收成令牌；L1 让明暗两态由 `(light:, dark:)` map 自动派生；L2 把动效按语义角色分档。**第四根是排版**——对一个文档站来说，字号与行高的秩序直接决定"读起来累不累"，比动效更基础。

本期只做三件事：**字号刻度、行高刻度、字体栈令牌化**（含把 FontSwitch 的 7 套预设接上令牌）。

**先划一条硬边界**：主题自身的字号写在 `node_modules` 里（实测 60+ 处，如 `toc.scss:67` 的 `0.875rem`、`page-meta.scss:74` 的 `13px`），**不可令牌化**。因此收敛范围严格限定在**我们自己的层**（`styles/` + `components/`），不试图覆盖主题内部的 h1–h6 与正文行高。

**本期不做**：改主题内部字号/行高；动图标字形尺寸（见 2.1）；引入 font-weight 刻度；引入第三方字体或排版库；引入 `<link>` 预加载/字体子集化。

## 二、核心设计

### 2.1 字号：按「语义刻度」分档，对齐 Tailwind

现状的形状**不是"值太多"，而是"值挤在一起"**——自有层 50 处文本字号跨 13 个取值，其中 `0.70 / 0.72 / 0.75 / 0.78 / 0.80 / 0.82 / 0.85` 这 7 个值全部落在 `11.2px ~ 13.6px` 的 **2.4px 区间**内。这不是刻意的层级，而是"每次改一点"的累积。这与 L2 面对 `0.22s / 0.25s` 是同一类债。

| 令牌           | 值       | ≈px@16 | 语义角色                               | 收敛的原值                          |
| -------------- | -------- | ------ | -------------------------------------- | ----------------------------------- |
| `--jg-fs-xs`   | 0.75rem  | 12     | 徽标、极小标签、角标                   | 0.70 / 0.72 / 0.75 / 0.78           |
| `--jg-fs-sm`   | 0.875rem | 14     | 密集 UI 小字：表单提示、meta、控件标签 | 0.80\* / 0.82 / 0.85 / 0.90 / 13px  |
| `--jg-fs-base` | 1rem     | 16     | UI 正文 / 控件基准                     | 0.95 / 0.96 / 1 / 16px              |
| `--jg-fs-lg`   | 1.125rem | 18     | 次级标题                               | 1.16（`GlobalUnlock.vue` 面板标题） |
| `--jg-fs-xl`   | 1.25rem  | 20     | 面板 / 对话框标题                      | 1.16 → 同上，按用途归 `lg`          |

> \* `0.78` / `0.80` 归 `xs` 还是 `sm` **逐处看语义判断**（表格头/角标→`xs`；控件标签/可点击文字→`sm`），不是机械替换。

**为什么不用"最贴近现状的一套"**：现状 `0.75 / 0.8125 / 0.875 / 1` 步长仅约 1px，肉眼不可辨，留 3 档等于留 3 个无法区分的选项。对齐 Tailwind 的代价是 `0.78~0.82` 那批值单点最多变 **+1.3px**，且集中在 `DocEditor/`——一个**仅 dev serve 可见、不进构建产物**的目录，线上零影响（见 6.6 实测）。用 ≤1.3px 换一套能心算、能判断归属的刻度，划算。

**边界（明确排除）**：两处固定 px 配对其实是**图标字形尺寸**，不是文本层级——`GlobalUnlock.vue:342-343`（`.close-btn` 的 × 号，18px/28px 装进 28×28 按钮）、`ClickImagePreview.vue:149-150`（30px/38px 装进 40×40 按钮）。图标字号必须锁定 px（随用户字号缩放会破版），**原样保留、不纳入刻度**。

### 2.2 行高：三档命名，覆盖全部现有场景、零视觉变化

| 令牌              | 值  | 语义角色           | 位置                                                         |
| ----------------- | --- | ------------------ | ------------------------------------------------------------ |
| `--jg-lh-tight`   | 1.3 | 密集单行 / 选项行  | `FontSwitch.vue`                                             |
| `--jg-lh-normal`  | 1.6 | 常规 UI 文本、段落 | `NewPageDialog.vue`、`GlobalUnlock.vue`、`UnlockContent.vue` |
| `--jg-lh-relaxed` | 1.7 | 长文阅读 / 编辑器  | `MarkdownEditor.vue`                                         |

三档**各自都对上现有取值**，这一步是纯"登记 + 命名"，风险最低。行高令牌一律**无单位数字**（继承时不锁死父级字号，CSS 最佳实践）。

### 2.3 字体栈：把权威收进 palette，让 FontSwitch 消费令牌

沿用 `--vp-font` / `--vp-font-heading` / `--vp-font-mono` 作为唯一契约，**不另起 `--jg-font-*` 命名空间**去当"第二套真相"。做三件事：

1. **补登记 `$vp-font-mono`**（带引号字符串）。它此前**从未在我们层声明**，静默继承主题默认栈（`templates/palette/font.scss`），意味着代码字体不在控制面上、主题升级即漂移。显式声明即覆盖主题的 `!default`。
2. **把 7 套预设栈从 TS 迁进 palette**，各生成 `$jg-font-<key>`（`system` / `web-sans` / `misans` / `theme` / `noto-serif` / `wenkai` / `kuaile`）。其中 `system` 直接 `$jg-font-system: $vp-font;`——**"默认字体栈"在仓库内自此只有一处真相**。
3. **`fontOptions.ts` 只留元数据**（`key` / `label` / 懒加载 `cssSheets`），新增 `fontStackVar(key) => \`var(--jg-font-${key})\``；`FontSwitch.vue`的`applyFont()` 与面板预览行都改用该令牌。

> **为什么 `base` / `heading` 引用令牌后仍然成立**：`root.style.setProperty("--vp-font", "var(--jg-font-web-sans)")` 属于**自定义属性引用自定义属性**——自定义属性的值允许是 `var()`，浏览器在计算 `font-family` 时链式解析到真实栈。面板预览行 `:style="{ fontFamily: 'var(--jg-font-system)' }"` 同理。这一点已在验收 6.4 用 `getComputedStyle` 的**解析结果**（而非变量是否存在）证伪过。
> CDN 主/备（jsDelivr 主 / registry.npmmirror.com 备）与"选中才懒加载"机制**原样保留在 TS**。

## 四、计划外发现

### 4.1 `GlobalUnlock.vue` 是死代码——L3 顺手改的是一个不进产物的文件（运行时证据）

排查"生产 CSS 里为何找不到 `var(--jg-fs-lg)`"时发现：`GlobalUnlock.vue` 的独有选择器（`.qr-tip` / `.unlock-modal` / `.unlock-fade-enter-active`）在 `dist/assets/*.css` 中**全部缺位**；而 `.lock-title` / `.lock-reason` / `.error-msg` 等看似同名的规则，其 scoped 哈希 `data-v-fb805e0d` 实为 `UnlockContent.vue` 所有（`UnlockContent.vue` 自带同名 `.lock-title`）。

三份独立证据指向同一结论：

1. `client.ts` 只注册 `UnlockContent`（`defineAsyncComponent`），**没有** `GlobalUnlock`；
2. 全仓 `docs/` 下对 `GlobalUnlock` 的引用只出现在**说明性注释**里（`palette.scss` / `index.scss` / `UnlockContent.vue` 的行文），无任何 import / 模板引用；
3. 全仓 `*.md` 中无 `GlobalUnlock` 使用痕迹。

**即 `GlobalUnlock.vue` 当前无人引用，其样式不进任何产物。** 影响：L2 与 L3 对该文件的所有改动（含 L2 的 `transition: all` 收敛、L3 的字号/行高令牌化）**都不在生产包内生效**。**本报告如实登记，不在 L3 内擅自删除**（去留见第九节）。

切换这两套预设后，`performance.getEntriesByType('resource')` 里**看不到**对应 CDN 条目。已排查：

- `<link rel="stylesheet">` **确实已注入 head**（`wenkaiLinks` / `kuaileLinks` 各 1 条）；
