# 阅读续读（上次阅读位置恢复）— 设计与实施计划

> 状态：计划（待批准）
> 需求（2026-10-05）：重启项目后，希望能回到上次离开的**页面**与**内容位置**；用户口中的"书签"指的是**自动续读**，不是收藏列表。
> 已确认的三项决策：① 范围只做自动续读（不含编辑器状态）；② 打开时**给入口、点了才恢复**，不自动跳转；③ 纯本地存储。

---

## 一、本期阶段与目标

阶段：**设计 + 实现（小改动，单期完成）**。

目标只有一个：**记住"最后一处阅读位置"，并在下次打开时提供一个一键回到原位的入口。**

验收的最终形态是：读到某篇文章中段 → 关掉浏览器 / 重启 dev server → 重新打开站点 → 看到"继续上次阅读：xxx"的轻量入口 → 点击 → 回到原来的页面和位置，且落点与目录联动的手感一致（标题停在导航栏下方 80px 那条约定）。

**明确不做**（本期）：

- 不做书签列表 / 收藏 / 命名 / 排序；
- 不做导出导入、不做跨设备同步；
- 不记录 DocEditor 的编辑文件与光标（用户已明确排除）；
- 不改主题的目录高亮与 `scrollBehavior`；
- 不做移动端特殊处理（沿用桌面行为，实施时确认不破版）。

---

## 二、现状证据：为什么现在是坏的

症状是两个独立问题叠加，**必须分开归因**，否则会在错误的地方修。

**问题一：页面本身从未被记住。** 全仓检索 `localStorage` / `sessionStorage` 的既有用途（字体预设 `javaguide-font-preset`、沉浸模式 `javaguide-layout-hidden`、编辑器偏好 `doc-editor-*`、编辑器草稿 `sessionStorage`），**没有任何一处记录"最后访问的路由"**。所以重开 `localhost:8080/` 必然落在首页。

**问题二：位置"存了但不可靠"。** 这个站的滚动链路是：

```
用户滚动
  → 主题目录滚动监听改写 location.hash
  → vue-router 的 scrollBehavior 滚回锚点
```

这条链路在 [DocEditor.vue](file:///d:/计算机人工智能/JavaGuide-main/docs/.vuepress/components/DocEditor/DocEditor.vue#L228-L231) 的注释里有明确记载，也正是 `SCROLL_GUARD_*` 那套守护逻辑存在的理由。

于是整页刷新时会出现：路由**拿不到 `savedPosition`**（该字段只在 SPA 内前进/后退时由 vue-router 填充），恢复只能交给浏览器原生的"跳到片段"，而它在图片 / Mermaid / 代码高亮渲染完成**之前**就执行了 → 落点漂移。

**结论**：位置信息其实部分存在于 URL 哈希里，但**时机不对、且没有兜底**；页面信息则完全缺失。

## 三、数据结构与存储

单个 localStorage 键，存**一条**（"最后一处"）：

```ts
/** 上次阅读位置在 localStorage 中的键名 */
export const READING_STORAGE_KEY = "javaguide-reading-last";

/** 一处阅读位置 */
export interface ReadingPosition {
  /** 路由 path，例如 /cs-basics/java/hashmap */
  path: string;
  /** 页面标题，用于入口文案 */
  title: string;
  /** 最近的上方标题锚点 id；页面无可锚定标题时为空串 */
  anchor: string;
  /** 相对该锚点的"已读进深"（px）；anchor 为空时表示绝对 scrollY */
  offset: number;
  /** 记录时刻的文档总高，用于恢复前判断内容是否已铺开 */
  docHeight: number;
  /** 记录时间戳 */
  savedAt: number;
}
```

**为什么多存一个 `docHeight`**：恢复时如果当前 `scrollHeight` 明显小于记录值，说明上方内容（图片、Mermaid）还没撑开，此时按锚点定位也会偏——需要重试而不是直接放弃。

**为什么键名用 `javaguide-` 前缀**：与 `javaguide-font-preset`、`javaguide-layout-hidden` 保持一致。

## 四、锚点定位算法（本期最核心的一段）

**不允许存绝对像素**。正文含懒加载图片、异步 Mermaid、Shiki 高亮，且 `RevealOnScroll` 会改元素类名影响布局——页面高度在加载后仍会变化，绝对像素必然落错。

复用本仓库既有的"锚点对齐"惯例（[scrollSync.ts](file:///d:/计算机人工智能/JavaGuide-main/docs/.vuepress/components/DocEditor/scrollSync.ts#L140) 就是这么算的）：

```
headingAbsTop = el.getBoundingClientRect().top + window.scrollY
```

并复用既有的**导航栏遮挡偏移**约定 `SCROLL_SYNC_PAGE_OFFSET_PX = 80`
（[docEditorState.ts](file:///d:/计算机人工智能/JavaGuide-main/docs/.vuepress/components/docEditorState.ts#L40-L44)：让标题停在 sticky 导航栏下方）。

**保存**（滚动到 scrollY 时）：

1. 取"当前小节标题"= 绝对高度 `≤ scrollY + navOffset` 的**最后一个**带 id 的 `h2/h3/h4`；
2. `anchor = 该标题 id`；
3. `offset = scrollY + navOffset − headingAbsTop`（即"越过该标题标题线多少"）；
4. 找不到任何标题 → `anchor = ""`，`offset = scrollY`（绝对兜底，接受可能偏移）。

**恢复**：

1. 按 `anchor` 找到元素，重新计算 `headingAbsTop`；
2. `targetScrollY = headingAbsTop − navOffset + offset`；
3. `window.scrollTo({ top: targetScrollY, behavior: "instant" })`。

**必须用 `"instant"`**：全局有 `html { scroll-behavior: smooth }`，不显式覆盖会让恢复被动画化、并与其它程序性滚动互相竞争（`SCROLL_GUARD_*` 踩过这个坑）。

**`navOffset` 在沉浸模式下必须为 0**：`layout-hidden` 时导航栏隐藏，没有遮挡。状态来自 `LayoutToggle` 的 `javaguide-layout-hidden`。

## 六、关键流程

**保存**：`scroll` 事件节流 → 算锚点 → 写 localStorage；另在 `visibilitychange`（`hidden`）与 `beforeunload` 补一次，保证"关窗即存"。

**恢复（点击入口后）**：

```
点击入口
  → 若当前路径 ≠ 记录路径：router.push(记录.path)
  → 等待路由就绪
  → 应用锚点恢复（instant）
  → 若 scrollHeight < 记录.docHeight：按节奏重试，直到成立或超时
  → 期间一旦捕获用户滚动输入（wheel/touchmove/keydown/pointerdown/mousedown）：
     立即放弃恢复，不再干预
```

"用户输入即释放 + 超时兜底"这套写法，直接复用 [DocEditor.vue](file:///d:/计算机人工智能/JavaGuide-main/docs/.vuepress/components/DocEditor/DocEditor.vue#L233-L289) 里已经验证过的 `SCROLL_GUARD_*` 模式，不另造一套。

## 八、风险与对策

| 风险                                                        | 对策                                                                                       |
| ----------------------------------------------------------- | ------------------------------------------------------------------------------------------ |
| **内容高度不稳定**（懒加载图 / Mermaid / 高亮）导致落点偏移 | 锚点定位（非像素）+ `docHeight` 就绪判断 + 限时重试                                        |
| **与主题哈希 scroll-spy 抢方向盘**                          | 不改 `scrollBehavior`；恢复用 `instant`；用户输入立即放弃                                  |
| **沉浸模式下多算 80px**                                     | `navOffset` 按 `javaguide-layout-hidden` 动态取 0 / 80                                     |
| **端口漂移使 localStorage 静默失效**                        | dev 脚本钉死 `--port 8080`；并在实现说明里写明"换端口 = 记忆丢失"这一事实                  |
| **记录的目标页已删除/改名**                                 | 捕获 `router.push` 失败 → 清除记录并提示"上次的页面已不存在"                               |
| **入口与既有悬浮元素撞位**                                  | 实施时先实测页面右下（主题回顶按钮）与左下现状，再定位置；使用既有 `--jg-z-float` 层级令牌 |
| **SSR 构建期无 `document`**                                 | 全部逻辑限制在客户端（延迟外壳 + `onMounted`），构建期不触碰 `window`                      |
| **多标签页互相覆盖**                                        | 接受"最后写入者胜"；不引入额外协调机制                                                     |

## 九、验收标准

1. 读到文章中部 → 刷新 / 重启 dev server → 出现"继续上次阅读：xxx"入口；
2. 点击入口 → 回到原页面，且落点与记录位置的偏差在**目视可接受范围**（标题位于导航栏下方 80px 这一约定成立）；
3. 在**图片密集页**与**含 Mermaid 的页**上重复第 1–2 步，落点仍正确（验证"高度不稳定"确实被锚点方案化解）；
4. 恢复过程中一旦滚动鼠标滚轮 → 恢复立刻停止，不再把页面拽回；
5. 沉浸模式（`layout-hidden`）下恢复不产生 80px 的多余偏移；
6. SPA 内点击侧边栏链接跳转 → **不触发**任何恢复（不被抢方向盘）；
7. `pnpm docs:build` 通过，且构建产物中不出现 `window`/`document` 相关的 SSR 报错。

```ts
// ResumeReading.vue —— 恢复编排的骨架（表达顺序与退出条件，不含细节）
const restore = async (pos: ReadingPosition) => {
  if (route.path !== pos.path) await router.push(pos.path);
  await nextTick();
  applyWithRetry(pos); // 内部：instant 定位 → 未就绪则按 RETRY 重试 → 超时/用户输入即停

```

**三点取舍说明**：

1. **入口而非自动跳转**——用户明确选了"点了才恢复"。自动跳转会在"你本就想从首页开始"时变成干扰。
2. **锚点而非像素**——这是对"本站内容高度不稳定"这一既有事实的正面回应，也让落点与目录联动共用同一套 80px 约定，不会出现两套对齐标准。
3. **不改 `scrollBehavior`**——宁可多写一个根组件，也不动主题与目录高亮共用的公共通道；这是本期最保守、也最不容易连累其它功能的选择。
